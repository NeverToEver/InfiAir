## 已知债务与开放发现

> 唯一登记处，只保留未关闭项；修复后直接删除。格式：是什么 / 为什么不现在做 / 收口条件 / 触发时机。

- **[低] 启动巨帧的主项是场景装载、不是着色器编译**：同机分段实测（M2 / Metal / 1280×720）显示 `Main._Ready` 装载约 570ms（无头同量级，即 CPU 侧：建 FX、加载贴图与场景），首帧含绘制约 110ms（无头 15ms，差值里才是着色器编译与管线初始化）；着色器预热（`ShaderPrewarm`）只能前移后一项。**为什么现在不做**：装载那半要压只能分帧构建表现层（HUD / 星空 / 后处理各摊几帧），代价是开机链路与入场时序要重新对齐。**收口条件**＝装载耗时降到首帧绘制的量级（**分段读数工具随探针宿主退役，需先恢复或另建同机读数**）。**触发时机**＝玩家反馈启动慢，或下次要动开机链路与表现层构建顺序时。
- **[中] 一批自动判据随 2026-09-18 门禁裁剪退役，改由人工核对**：存档 / 设置写读对称、balance 键存在性与死键、文案键存在性、代码默认值与 json 对账、真实时间使用清单（归属口径见 `DESIGN_BASELINE` §2.10 / §2.11）。**为什么现在不做**：这些判据曾被判定为「回归面大于被测代码」，退役是当时的显式决策。**收口条件**＝出现一次因缺少判据而漏过的真缺陷（届时按需从 git 历史恢复对应脚本）。**触发时机**＝改存档字段 / 设置项 / 语义化文案 / 计时基准时，按纪律人工核对两侧。
- **[低] 玩法层随机未种子化**：表现层随机已确定化（星场 / 残景 / 特效），玩法层（暴击、标记、刷怪、Boss 走位、迷雾触发）仍走 `GD.Rand*` 默认序列——「输入 + 种子 = 可复现的一局」只做到一半（口径与出处见 `REFERENCES.md` §4.3）。**为什么现在不做**：无回放 / 排行榜需求，收益不落地。**收口条件**＝表现层与玩法层共用可注入取值源，冒烟趟可固定种子复跑。**触发时机**＝要做回放保存，或某类缺陷只能靠复现整局定位时。
- **[低] lifesteal 超载层是死值**：吸血结算只判「层数 >0」（`CombatStateService.TryLifesteal`），超载到第 2 层无任何效果——白耗双倍价与超载槽，是加点面的静默陷阱（奖惩审计发现）。**为什么现在不做**：玩法系统扩展冻结，改节点语义属重启项。**收口条件**＝第 2 层有独立效果，或把 lifesteal 从超载可选面剔除。**触发时机**＝重启天赋语义扩展时。

## Decisions

> 一行制：**日期 决策** + 为什么 + 反转链。只记当前周期（2026-09-17 决策线重置起）；更早在 git 历史。本批之前的长条目原文见 `git show e9a4141:docs/ROADMAP.md`。

- **2026-09-19 标题屏展示机改机库轮展（`DESIGN_BASELINE` §1.17）**：人类指令「为主界面战机展示做随机系统，现有的多种战机随机展示」——展示机由 core `MachineBag` 无放回轮展（一袋六型各一次、跨袋不连出同型；**不逐次独立掷签**：六型里连出同型的概率 1/6，玩家一晚上回标题屏十几次必然撞见，那一瞬间读到的不是「随机」而是「没换」），铭牌写机型名与该型加成、标签随是否等于 `GameState.MachineId` 在「现役机型 / 机库展示」间切换；机型面板选定后仍立刻换成刚选的那一型（原有反馈保留）。判据钉在 `MachineBagTests`。反转链＝展示机改回 `GameState.Machine` 并删 `MachineBag` 与铭牌，即回「永远展示自己在飞的那一型」。
- **2026-09-19 标题屏补深空纵深层 + 远景战场改演出表驱动**：人类指令「背景上的元素也可以更复杂一些，让整体元素更多样的同时增加细节体验」——新增 `TitleBackdrop` 四层纵深（行星 / 残骸带 / 尘埃 / 航道浮标，取位单源 `TitleScreen.SkyZones`，避开标题区与展示位），远景战场由「每类各跑一条固定间隔计时器」改为 core `AmbientDirector` 的加权 + 逐类冷却抽取（固定间隔读起来是节拍器，不是战场），另补曳光火网 / 大型舰与母舰巡航 / 传感扫描三类演出与交火爆炸分档。判据钉在 `AmbientDirectorTests`；观感按准入判据随批收口（无人工验收）。反转链＝删 `TitleBackdrop` / `TitleTracers` / `AmbientDirector` 并把 `WzActs` 换回三条 `ScheduleWz` 定时器，即回上一版标题屏。
- **2026-09-19 机型补「代价」：五型各加一项减益，反转同日「只给加成不加惩罚」**（人类指令「这几个飞机不能只有正向的增益」）：每条特种型由「一项加成」改为「**一项加成 + 一项异轴代价**」（游隼 火力 −10% / 重锤 移速 −10% / 连弩 受伤 +12% / 壁垒 射速 −10.7% / 巨像 移速 −12%），标准型保持零加成零代价。依据＝能力预算（每个可选项都要有代价，否则六选一出无脑解；代价须无条件生效）与损失厌恶（损失体感约为等量收益的两倍，故代价幅度取加成的 0.5–0.7 倍），出处见 `REFERENCES.md` §4.16；三条规则与取值表在 `DESIGN_BASELINE` §1.17，判据钉在 `MachineRosterTests`（异轴 / 方向 / 比值带 / 数值表对账）。反转链＝删各型 `machines.*` 里的代价键并清空 `MachineSpec.Penalty` 即回纯加成形态。
- **2026-09-19 解冻「机体」：开局六选一（`DESIGN_BASELINE` §1.17）**：人类指令「加入不同的初始机型，各带一项加成（移速 / 攻击力 / 攻速 / 防御 / 血量）且各有一副外观」——即 2026-09-17 内容边界里冻结项的显式重启。落地为六型：**标准型**（无加成）保住既有玩家体验与旧档兼容（两处机型键缺失一律归一到它），五个特种型各一项加成、各一套确定性程序化外观；量级一律压在**亚一层增幅**之下（依据与锚定见 `REFERENCES.md` §4.15），本局不能换机（`run.json machine`），入口在标题屏 `M`。反转链＝删 `csharp/core/Machines/`、`MachinePanel.cs`、`balance.json machines.*` 与 5 套贴图即回单机体；旧档里留下的 `machine` 键会被忽略，不阻塞读档。

- **2026-09-19 游戏内数值管理器入口 + 标题屏安全重载**：入口在设置页「辅助与关于」页尾（可用条件两条：工具脚本存在于 res:// 且非 headless——构建工具不进发布包，导出包与无头冒烟里自行禁用），点按钮先用 HTTPRequest 异步探本机 8931 端口的身份串，在跑就 ShellOpen，没跑就按平台候选起 python3 再等它就绪。运行中改文件的冲突走**安全点重载**而非局内热重载：恢复 991177b 删掉的 ReloadBalance 三段式（Load + Apply + Events.ReloadConfig），标题屏每秒比一次文件 mtime、变了才重载。局内不重载的理由是消费者多数「启动读一次」且不可重跑——Spawner 的敌机表是原地 merge（重跑非幂等）、Player 重跑会白送满无敌并回满燃料、Enemy 的动效配置每进程只读一次；下一局进 main 会重建这些实例，故「回标题屏生效」既安全又完整（另注：编辑器用 os.replace 原子写，游戏只会读到旧值或新值，不会是半个文件）。反转链＝三处独立可撤（设置页那一节 / BalanceEditorLauncher / TitleScreen 轮询 + GameState.ReloadBalanceIfChanged），删掉即回到「重启游戏才生效」。
