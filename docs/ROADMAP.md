## 已知债务与开放发现

> 唯一登记处，只保留未关闭项；修复后直接删除。格式：是什么 / 为什么不现在做 / 收口条件 / 触发时机。

- **[低] 启动巨帧的主项是场景装载、不是着色器编译**：同机分段实测（M2 / Metal / 1280×720）显示 `Main._Ready` 装载约 570ms（无头同量级，即 CPU 侧：建 FX、加载贴图与场景），首帧含绘制约 110ms（无头 15ms，差值里才是着色器编译与管线初始化）；着色器预热（`ShaderPrewarm`）只能前移后一项。**为什么现在不做**：装载那半要压只能分帧构建表现层（HUD / 星空 / 后处理各摊几帧），代价是开机链路与入场时序要重新对齐。**收口条件**＝装载耗时降到首帧绘制的量级（**分段读数工具随探针宿主退役，需先恢复或另建同机读数**）。**触发时机**＝玩家反馈启动慢，或下次要动开机链路与表现层构建顺序时。
- **[中] 一批自动判据随 2026-09-18 门禁裁剪退役，改由人工核对**：存档 / 设置写读对称、balance 键存在性与死键、文案键存在性、代码默认值与 json 对账、真实时间使用清单（归属口径见 `DESIGN_BASELINE` §2.10 / §2.11）。**为什么现在不做**：这些判据曾被判定为「回归面大于被测代码」，退役是当时的显式决策。**收口条件**＝出现一次因缺少判据而漏过的真缺陷（届时按需从 git 历史恢复对应脚本）。**触发时机**＝改存档字段 / 设置项 / 语义化文案 / 计时基准时，按纪律人工核对两侧。
- **[低] 玩法层随机未种子化**：表现层随机已确定化（星场 / 残景 / 特效），玩法层（暴击、标记、刷怪、Boss 走位、迷雾触发）仍走 `GD.Rand*` 默认序列——「输入 + 种子 = 可复现的一局」只做到一半（口径与出处见 `REFERENCES.md` §4.3）。**为什么现在不做**：无回放 / 排行榜需求，收益不落地。**收口条件**＝表现层与玩法层共用可注入取值源，冒烟趟可固定种子复跑。**触发时机**＝要做回放保存，或某类缺陷只能靠复现整局定位时。
