## 1. 现状取证：难度与压力是怎么爬的

### 1.1 难度乘数闭式

`DifficultyCurve.Compute`（`csharp/core/Progression/ProgressionCurves.cs:107-131`）与 `balance.json:progression`：

```
D(t, k) = 1 + per_boss_kill·k + floor(t / time_step_seconds) · time_step_seconds / 600 · per_ten_minutes
        = 1 + 0.6·k + 0.15·t        （t 单位分钟，k = Boss 击杀数，量化步 30s）
```

- 时间斜率 **+0.15/分钟**；每杀一只 Boss **+0.6 = 相当于 4 分钟墙钟**（`ProgressionCurves.cs:130`）。
- **Boss 击杀项与总 D 均无上限**；只有 1e6 秒的防御性钳制（`ProgressionCurves.cs:117-120`）。
- 三档难度**共享同一个 D**——`DifficultyCurve` 不接收难度档（`ProgressionCurves.cs:107-108`），档位是独立乘区（`GameState.Constants.cs:33-64`）。

纯时间基线（k=0）：

| t | 0 | 2min | 5min | 10min | 20min | 30min | 60min |
|---|---|---|---|---|---|---|---|
| D | 1.00 | 1.30 | 1.75 | 2.50 | 4.00 | 5.50 | 10.00 |

### 1.2 D 作用到哪些量（不对称是核心）

| 量 | 公式 | 斜率 | 上限 | 位置 |
|---|---|---|---|---|
| 杂兵 / 精英 HP | `×(1 + 0.25(D−1))` | 0.25 | 无 | `Enemy.cs:281-289` |
| **Boss HP** | `hp_base·hp_mults·**D**` | **1.00** | 无 | `Boss.cs:674-679` |
| 敌方伤害（全部） | `×(1 + 0.20(D−1))` | 0.20 | 无 | `Bullet.cs:126`、`EnemyFx.cs:9-11` |
| 杂兵 / 精英速度 | `×(1 + 0.10(D−1))` | 0.10 | **无** | `Enemy.cs:297-301` |
| 波次间隔 | `÷ (1 + 0.15(D−1))`，下限 `2.5s` | — | **2.5s 触底** | `Spawner.cs:616-628` |
| 波次规模 | `lerp(3→5, t/300s)`，**与 D 无关** | — | **5 触顶** | `Spawner.cs:281-285` |
| 精英波数量 | `elite_wave_size = 1` 固定 | — | **恒 1** | `balance.json` spawner |
| 敌机开火间隔 | **不吃 D**（只吃 DDA） | — | — | `Enemy.cs:292,772` |
| Boss 攻击密度 / 弹速 / 弹数 | **只看难度档，不看 D** | — | — | `Boss.cs:1220-1301` |
| Boss 逃跑计时 / 阶段 / 狂暴 | `50s` / `0.7` / `0.3` 固定 | — | — | `Boss.cs:451,416-417,863-869` |
| 事件触发概率与奖励 | **常量，不吃 D** | — | — | `GameEventManager.cs:150-189` |
| 玩家火力 / 血量 / 回血 | **不吃 D**，只靠天赋/增幅/档位 | — | 有硬顶 | `Player.cs:746-747` |

三处最不对称：

1. **Boss HP 斜率是杂兵的 4 倍**（1.0 vs 0.25）。D=10 时 Boss1 HP = 10400（medium），而杂兵 HP 仅约 211–234，比值从开局的 16× 拉到 44×。
2. **速度无上限**，而速度是唯一直接破坏「可反应性」的量。
3. **节奏维度（波间隔、波规模、精英数、弹密度、弹速）在 5–11 分钟内全部触顶**，之后压力**只剩数值**。

### 1.3 玩家侧的三重硬顶

| 封顶机制 | 效果 | 位置 |
|---|---|---|
| 天赋软上限 | 超过 softcap 每级效率 −0.25，下限 0.25 | `TalentEconomy.cs:205-229` |
| 缓存衰减 | 原始点 >20 后每点价值 0.9→0.1（不可逆）；100 原始点只有 31.6 有效 | `TalentEconomy.cs:137-148` |
| 点数收入减速 | 里程碑阈值每循环 ×1.35，但**每档恒给 2 点** | `ScoreService.cs:50-53` |

推算（medium，估算得分率）：玩家 DPS 从裸装 66.7 到满攻击软上限约 1368（×20.5），有效 HP 从 100 到 600（×6.0）；但**点数收入随时间是减速的**，而 D 是**线性加速的**——两条曲线必然交叉，之后不可逆。

### 1.4 当前必死曲线到底靠什么致死

综合三份取证：**普通波次随时间变简单**（30min 敌方 HP 仅 ×2.125，玩家 DPS 可达 ×6~20）；**真正的检查只在 Boss 单点**——50s 窗口内 `有效DPS × 43.1 ≥ 800·hpMult·hpTier·D`（狂霸锁血 6.9s 占掉一个输出窗，`Boss.cs:839-850`、`EnrageSequence.cs`）。打不死则 Boss 逃跑，**逃跑不推进 `_nextBossScore`**（`Spawner.cs:491-509`），80s 后同型 Boss 再来——后期变成「每约 130s 一只无奖励 Boss」的纯消耗循环，同时 D 仍按时间上涨。

## 3. 症结排序

把上面的对照收敛成一句话：

> **InfiAir 把一款本应靠「弹幕密度与模式复杂度上升」的弹幕游戏，做成了只靠数值膨胀的无尽曲线。** 5~10 分钟后所有节奏维度触顶（波间隔 2.5s、波规模 5、精英恒 1、弹速/弹密度/开火频率不随 D 增长），压力只剩「敌人更肉、打你更痛、Boss 血条无上限」；而玩家侧成长被三重硬顶锁死、奖励速率还在**反向减速**。于是普通战斗越后期越简单（无聊），Boss 单点检查越来越不可过（挫败），中途没有任何可读的里程碑或收束口径（既不觉公平也不觉有进展）。同时战斗反馈缺顿帧、震动用非 trauma 模型，造成「打击感发平」——这正是「体验观感不尽人意」的机制级成因。

按影响面与可修性排序：

| 优先级 | 症结 | 为什么最痛 |
|---|---|---|
| **P0-1** | 命中无顿帧，震动非 trauma 模型 | 「打击感发平」的直接元凶；纯实现可改，不动玩家可感数值 |
| **P0-2** | Boss 狂暴「检查点锁血」会把 HP 抬回 30%（`Boss.cs:845-850`） | 明确的实现缺陷：爆发够高可跳过整段 ENRAGE，一般情况等于给 Boss 回血 5 个百分点 |
| **P0-3** | 节奏维度全员触顶，后期只堆数值 | 弹幕游戏的难度本应是「密度/模式」，现状与品类惯例相悖 |
| **P0-4** | Boss HP 斜率是杂兵 4 倍 + 无上限，且逃跑不成阻力 | 必死点由 build 方差决定、不可复盘；后期退化为「每 130s 无奖励 Boss」 |
| **P0-5** | 奖励与难度反向（收入减速 / 同酬 / 擦弹连击失效） | 复利式劣势：越后期越难攒点，越攒不到点越打不动 |
| **P1-1** | 必死曲线缺收束口径与命名档位 | 玩家不知道「打到哪算赢」，失败归因落到游戏（Juul：玩家偏好自责） |
| **P1-2** | 缓存衰减不可逆 + 入口隐蔽 | 新手在 6–8 分钟后**毫不知情地**持续亏损 |
| **P1-3** | 受击 DDA 名为动态难度、实为固定呼吸，且叠加清屏+免伤 | 削弱了「压力无界」的设计意图，也让「被击穿」的因果变模糊 |
| **P1-4** | 精英炮塔等事件风险远大于回报；fog 全为纯负反馈 | 玩家理性选择是规避/拖超时，事件系统变成负资产 |
| **P2-1** | 专注惩罚名存实亡（只有 extra_life 能触发）、互斥锁对 max1 节点无感 | 机制与设计意图脱节（代码注释已自认） |
| **P2-2** | hard 净点数节奏 = medium（3/1.5 = 2），与 DESIGN_BASELINE「Hard buff pacing fastest」冲突 | 文档与实现不符；高难玩家「白难」 |
| **P2-3** | 分数不显示，里程碑/点数无可见反馈 | 玩家无法把「打得好」与「点数变多」关联，学习曲线断裂 |

## 4. 改进建议

每条给：现状 / 建议 / 依据 / 代价 / **待确认取值**。标记「⚙️ 纯实现，不触及玩家可感取值」的条目可立即做；其余须人类确认取值。

### 4.1 手感与观感（先做，见效最快）

**A1 ⚙️ 加入层级化命中顿帧（hitstop）**

- 建议：按事件权重给三档顿帧——普通命中 2–3 帧（约 35–50ms）、暴击 4–6 帧（70–100ms）、击杀/破盾 8–12 帧（130–200ms）；Boss 阶段转换另给一档。实现建议用 `Engine.TimeScale` 短时冻结并要求「计时器忽略时间缩放」（Godot juice 包的做法），或对单个实体做局部定格以避免全局卡顿。
- 依据：行业惯例 40–250ms、随伤害单调递增（[Saltmire Juice 默认 80ms](https://github.com/saltmire/saltmire-juice)、[SmashWiki Hitlag](https://www.ssbwiki.com/Hitlag)、[GGST 11/21/31F](https://www.dustloop.com/w/GGST/Frame_Data)）。Godot juice 框架把它列为 2D 手感的四层之一（sprite / camera / time / particles），缺任一层就会「发平」。
- 代价：**顿帧会轻微改变输入与判定的时间感**，且高频命中（后期同屏多目标）下若不做「合并/上限」会造成卡顿与眩晕；须配 `ReduceFlash` 联动与时长上界。
- 待确认取值：三档顿帧的毫秒数（建议 40 / 90 / 160ms）——玩家可感手感值，归人。

**A2 ⚙️ 屏幕震动改 trauma 模型 + 层级化**

- 建议：改用 `offset = maxOffset × trauma²`、每帧 `trauma = Clamp01(trauma + stress)`、线性衰减 1.5/s、Perlin 连续噪声、频率 25；把现有各震源映射为 trauma 增量（轻 0.1–0.2 / 中 0.2–0.4 / 重 0.5–0.8 / 满屏 0.8–1.0），同一帧多事件取最大值而非叠加。
- 依据：[Eiserloh GDC 2016](https://www.gdcvault.com/play/1023146/Math-for-Game-Programmers-Juicing) 为事实标准；[Roystan](https://roystan.net/articles/camera-shake.html) 给出 frequency 25、衰减 1.5/s。
- 代价：现有 `effects.shake.*` 键的语义从「像素振幅」变为「trauma 增量」，属**同一事实两处口径**的风险——须同步 `balance.json` 注释与消费点，且旧档无影响（震源不存档）。
- 待确认取值：衰减速率与各档 trauma 增量（建议 1.5/s；0.15 / 0.3 / 0.65 / 1.0）。

**A3 ⚙️ 后处理与闪烁强度补齐独立可调项**

- 建议：在设置页把「世界后处理强度」与「顿帧强度」做成 0–100%（现有 `WorldPostFx` 是布尔开关、`ReduceFlash` 是二值）。默认值须不触发 XAG 118 的 >3 次/秒 / ≥20% 面积判据。
- 依据：[XAG 117](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/117) 要求全屏效果可关或 0–100%；Halo Infinite 的 4 条滑条为实例。
- 代价：新增设置项 → 须过 `check_settings_symmetry.sh` + 设置页开页冒烟 + 文案键。
- 待确认取值：新增设置项本身属「新增设置项」——归人（须先提议）。

**A4 ⚙️ 后处理强度与弹幕可读性的冲突复核**

- 建议：保持常态弹幕段「洁净」（bloom 不糊化小弹体、颗粒不降小目标信噪比），仅在 Boss 转阶段/满屏爆炸短时提升；建议加一次针对「敌弹在 bloom 下的边缘可辨度」的窗口化过目。
- 依据：Boss 设计原则「保持视觉洁净以免遮盖意图」（[RPS 转述 Digital Dragons 大师课](https://www.rockpapershotgun.com/i-attended-a-tomb-raider-and-horizon-developers-boss-design-masterclass-and-came-away-both-weary-and-enchanted)）；弹幕可读性优先于观感。
- 代价：属观感，无法自动化 → 登记人工项 + 代码护栏（强度上界断言）。

### 4.2 难度曲线结构（须确认取值）

**B1 统一并重校三条斜率的层级关系**

- 现状：杂兵 HP 0.25 / 伤害 0.20 / 速度 0.10，Boss HP 1.00。
- 建议方向：让「Boss HP 斜率 > 杂兵 HP 斜率 > 伤害斜率 > 速度斜率」保持单调，但**压缩 Boss 与杂兵的差距**（Boss 从 1.0 降到约 0.5–0.6），**抬高杂兵 HP 斜率**（0.25 → 0.35–0.45），使普通战斗不再随时间变简单。
- 依据：行业刻意让 HP 缩放缓于伤害但两者都低于玩家成长（RoR2 +30%/+20%；Brotato 2.25×）；**斜率分裂是当前「两极」的根因**。
- 代价：直接改变玩家可感的击杀手感与 Boss 难度 → 归人；改动面覆盖 `balance.json` 的 `hp_ramp_factor` / `damage_ramp_factor` / `speed_ramp_factor` 与 Boss HP 消费点，须同步单测与探针。
- 待确认取值：

  | 选项 | hp_ramp_factor | damage_ramp_factor | speed_ramp_factor | Boss HP 斜率 | 实测/依据 | 代价 |
  |---|---|---|---|---|---|---|
  | A 建议（默认落地，待确认） | 0.40 | 0.20 | 0.10 | 0.55 | 对齐「HP 缩放缓于伤害、两者低于玩家成长」；消除杂兵无压力与 Boss 成墙 | Boss 前期更脆，需重校 `hp_base` |
  | B 保守 | 0.30 | 0.20 | 0.10 | 0.75 | 减小改动幅度 | 两极只缓解不消除 |
  | C 维持 | 0.25 | 0.20 | 0.10 | 1.00 | 现状 | 症结保留 |

**B2 给速度设硬上限**

- 建议：`速度 = ×(1 + 0.10(D−1))` 加硬顶（例如 ×1.75–2.0，对齐 Brotato ×2.75 的下端）。
- 依据：**[一手]** Brotato 速度硬顶 ×2.75；VS `speedPerMinute 0.005`。速度是唯一直接破坏可反应性的量。
- 代价：削弱后期「紧迫感」，需用密度补偿 → 与 B3 绑定。
- 待确认取值：速度倍率硬顶（建议 ×1.8）。

**B3 把「节奏维度」重新接入 D，让后期压力回到密度与模式**

- 建议（三个可选杠杆，按实现成本排序）：
  1. 精英波数量随 D 增长（现恒 1）——最便宜，直接复用现有精英波路径；
  2. 敌机开火间隔随 D 缩短，但设「弹速/间隔地板」（现完全不吃 D）；
  3. Boss 攻击的 `counts.*` 密度随 D 增长（现已按档位有增量机制，只需把 D 接入同一入口）。
- 依据：RoR2 Director 预算随 coeff 涨 → 强怪/精英占比上升；Brotato 每 10 波 +1 精英、双 Boss；20MTD **并发上限不变、靠频率**——三条都在「让后期更密而非更肉」。
- 代价：密度提升对性能与可读性影响大 → 须新增同屏上限护栏 + 无头压力探针；玩家可感 → 归人。
- 待确认取值：精英数量随 D 的步进（建议每 +2.0 D 增 1 只、上限 3）、开火间隔地板（建议 1.2s）。

**B4 给 D 加「软上限 + 减速带」**

- 建议：保留必死（D1 既定方向），但让斜率分段衰减而非无限线性，例如 D 超过某阈值后时间项斜率减半、Boss 项递减。同时在 HUD 显示「到下一档的进度」。
- 依据：Brotato 用「EF 三角数 + wave20 后 harvesting 反向」制造明确的加速段；VS 有硬收尾。**关键是曲线可被读出**，而非形状本身。
- 代价：直接改变必死时点 → 归人；须与 B1 一起调，单独调会互相抵消。
- 待确认取值：D 的减速起点与衰减系数（建议 D>6 后时间项斜率 ×0.5）。

**B5 ⚙️ 修 Boss 狂暴「检查点锁血」**

- 现状：`Boss.cs:845-850` 在 `Hp < 0.3·MaxHp` 时把 HP **抬回** 0.3·MaxHp；且该分支要求 `Hp > 0`，故单发击杀可跳过整段 ENRAGE。
- 建议：把「进入狂暴」与「HP 下限」解耦——用布尔标志位记录已触发，HP 只受 `Max(0)` 约束；转阶段清弹与无敌照常给，但不回血、不跳段。
- 依据：属实现缺陷与「血条只降」的可读性冲突，非平衡取舍。可用 core 单测钉死（「狂暴触发不改变 HP 单调性」）。
- 代价：无玩家可感取值争议（修复的是错误行为）；Boss 实际难度略升（不再回血），若需抵消由 B1 确认。

### 4.3 奖励与经济（须确认取值）

**C1 让奖励与难度耦合，止住复利式劣势**

- 现状：击杀分/事件奖励常量；里程碑阈值 ×1.35^cycle 而每档恒 2 点。
- 建议（三选一或组合）：
  1. **击杀分随 D 增长**（`score × f(D)`），使单位时间收入不被 HP 膨胀稀释——对齐 RoR2 的「货币也通胀」；
  2. **里程碑每档点数随 D 递增**，使点数收入不减速；
  3. **里程碑阈值改用 D 归一化**（阈值按 D 缩放），使收入速率恒定。
- 依据：StS 三选一每战斗固定、RoR2 `moneyCost × coeff^1.25` 双轨。**现状是「怪更肉但同酬」，比两种惯例都差。**
- 代价：直接影响天赋点数收入速率与整局成长曲线 → 归人；改动面覆盖 `ScoreService`/`TalentService`/`MilestoneCurve`，须补 core 单测。
- 待确认取值：建议方案 1（击杀分 `×(1 + 0.15(D−1))`，与伤害 ramp 同族）——待确认。

**C2 放大擦弹与连击，让风险回报成立**

- 建议：擦弹分接入难度与连击乘区（或给擦弹独立倍率阶梯）；连击窗口与波间隔对齐（例如窗口 ≥ 最大波间隔 + 余量），使跨波连击可达、×2 成为可追求目标。
- 依据：DDP 蜜蜂 100→100,000、NO MISS 200,000；Ikaruga 连锁上限 25,600。「擦弹 = 贪分」是弹幕系核心动机，也才能兑现 2.8px 小判定的设计意图。
- 代价：得分膨胀会推快里程碑 → 须与 C1/里程碑曲线一起调；玩家可感 → 归人。
- 待确认取值：连击窗口（建议 3.0 → 5.0s）、擦弹基准分与倍率（建议 10 → 30，且吃连击）。

**C3 事件奖励 ≥ 风险成本（2–3×）**

- 建议：精英炮塔按击破数给分并设「全歼加成」，使期望收益 ≥ 同时间刷杂兵；或给事件附加独占资源（RP / 天赋点），使其不与刷怪争同一收入轴。
- 依据：经验锚点「回报约为惩罚 3 倍」（[Psychology of Games 引 Nik Davidson](https://www.psychologyofgames.com/2017/12/using-psychology-to-design-leveling-systems/)）；RoR2 神龛「55% 有产出、Legendary 1%」用低概率高光制造记忆点。
- 代价：改变玩家对事件的取舍 → 归人。
- 待确认取值：精英炮塔单座分与全歼加成（建议单座 150 + 全歼 500 → 合计 ≥ 同窗口刷怪收入）。

**C4 fog 干扰事件加补偿或按难度门控**

- 建议：给每个 fog 事件配一个小额奖励（分或临时增幅），或改为**玩家可选的「高风险雾区」**（对齐 VS Curse：自选风险换战利品）；至少让触发概率/强度随难度分档，而非 easy/hard 同受。
- 依据：VS Curse +10%/rank 上限 +50% 是「自选难度换战利品」的标杆；纯负反馈事件在业界多被判为「减 fun 不加压」。
- 代价：改变难度体感与奖励结构 → 归人。
- 待确认取值：fog 补偿形式与数值（建议每事件 100–200 分或 3s 全局减伤）。

**C5 缓存衰减改为正向补偿，或加宽安全阈值 + 强化可见性**

- 建议（择一或组合）：把「溢出衰减」改成 StS 式**正向保底**（花掉点数后衰减部分回补，或每 N 点保底一个未衰减点）；把 `safe_threshold` 从 20 提高到更高；把「点数已溢出」做成**显式、主动的提示**（HUD 常驻「可加点」徽标 + 首次溢出时的一次性提示），不再只靠变色。
- 依据：StS pity offset 是正向保底；「惩罚 + 隐蔽 + 不可逆」三重叠加对新手是纯负面，且与「可读性即公平」的公平判据冲突。
- 代价：削弱「溢出压力」的设计意图 → 归人；面板入口与提示属 UI 改动，须过 `check_ui_copy.sh`。
- 待确认取值：`safe_threshold`（建议 20 → 30）与是否引入正向回补。

**C6 ⚙️ 里程碑/点数获取的可见反馈**

- 建议：HUD 不显示分数（既定），但可在里程碑达成时给一次短促提示（「里程碑 +2 天赋点」），并在缓存芯片上常驻「距下一里程碑进度」。
- 依据：玩家无法把「打得好」与「点数变多」关联 = 学习曲线断裂；行业共识是奖励要可感知（可读性即公平）。
- 代价：新增文案键 → 过 `check_ui_copy.sh`；不改任何数值，属纯实现。

### 4.4 机制一致性（须确认取值）

**D1 重校专注惩罚与互斥锁的作用面**

- 现状：专注惩罚阈值 7，但只有 `extra_life`（max 10）能触发，其余节点 max ≤5、风险加点后 ≤6（`TalentEconomy.cs:231-243` 注释自认脱节）；互斥锁对 max1 节点无感。
- 建议：要么把阈值降到能被多数高投入节点触发（例如 4–5），要么明确该机制只服务 `extra_life` 并收窄文档口径、不再宣称全局惩罚。
- 依据：机制与设计意图脱节＝玩家读不懂惩罚从哪来，属公平性（因果明确）问题。
- 待确认取值：`focus.threshold`（建议 7 → 5，或维持 7 但改文档口径）。

**D2 ⚙️ 修正 hard 的净点数节奏与文档口径**

- 现状：hard 分数 ×3 / 里程碑 ×1.5 → 净倍率 2× = medium（`GameState.Constants.cs:38-64`）。`DESIGN_BASELINE.md:33` 把「Hard-mode buff pacing fastest（×3 score, ×1.5 thresholds）」标为 **intentional**——即设计意图是「hard 玩家在更强的敌机下，成长节奏仍不低于 medium」。但字面口径「fastest」不成立（3/1.5 = 2 = medium 的 2/1），且 hard 敌机 HP ×1.5 / 速度 ×1.2 / 刷怪间隔 ×0.8 → 击杀效率更低，实际点数节奏很可能**低于** medium。
- 建议：二者取一——要么把 `hard.milestone` 从 1.5 下调（使 hard 净节奏 = 3，字面兑现「fastest」），要么把文档口径改写为「hard 与 medium 同速、以更高的敌人强度换取同样的成长，收口取荣誉而非战力度」。
- 依据：文档与实现不符属一致性缺陷；`AGENTS.md` §7 要求跨面改动先落文档。这也正是「该走单轨荣誉还是双轨补偿」（E2）必须先定的原因。
- 代价：下调 milestone 会加快 hard 的点数收入 → 归人。**若选「改文档」则属纯文档修正，可立即做。**

### 4.5 必死曲线的收束与长线（方向决策）

**E1 给必死曲线一个可读的收束口径**

- 建议：定义「本局达成」阈值并显式告知（例如「击杀第 8 只 Boss / 存活 20 分钟即达成」），达成后死亡仍记为本局成功；同时把 D 映射到命名档位（对齐 RoR1 的 10 档命名、Brotato 的「wave 20 后死亡算胜」）。
- 依据：Brotato 官方 wiki 原文「确保你的灭亡」+「打过 wave 20 死亡算胜」；Juul 实证「失败几次后通关」评分最高、玩家偏好「失败归因于自己」。**这是把「必死」从挫败变成目标的最低成本手段。**
- 代价：属新增玩家可见内容与文案 → 归人。
- 待确认取值：达成阈值（建议：第 10 只 Boss 或 20 分钟，取先到者）。

**E2 高难度只加荣誉 / 或明确双轨**

- 建议：明确三档难度的定位——要么「高难只加荣誉分、不加战力」（街机传统，InfiAir 现接近此形态，但需把点数收入与难度解耦并写清），要么「双轨：高难敌强但资源也多」（RoR2 形态，需 C1 落地）。当前是模糊中间态。
- 依据：Ikaruga 连锁「只影响分数与排名」是最干净的「分数=荣誉」证据；StS Ascension 是「高难资源更少」的反向范例。**必须选一条，否则玩家无法判断该选哪档。**
- 代价：方向决策 → 归人；影响三档难度的数值表与文档。

**E3 长线动机（方向开放项）**

- 现状：纯街机流，无登录/排行榜/局外成长（2026-09-08 用户指令）；本局全树 218 点不可达。
- 建议：若要保持纯街机，长线动机靠「命名档位 + 达成判定 + 练习/教程 + 本局内的构筑多样性」；若日后放松，再评估轻度 meta。
- 依据：无 meta 的行业支柱是排行榜、固定学习曲线（3 命起）、解锁机体/模式、成就、练习模式。

## 7. 明确不做与存疑

- **不改判定点 2.8px**：该值落在弹幕系正统档位（Touhou6 为 2.5px），视觉 2.4× 亦为正统；问题不在判定大小，在「受击三重复合」与「擦弹回报不足」。

- **不擅自改任何玩家可感数值**：本文所有取值均为建议，落地须人类确认并在提交正文标注。
- **存疑（须实现前复核）**：
  - T2 的「玩家有效 DPS」为静态推算（裸装 66.7 → 满攻击软上限约 1368 → 含母舰峰值更高），**未经实机校验**；TTK 与 Boss 逃跑临界点随操作与 build 波动大，建议先补实机埋点再定 B1 的具体值。
