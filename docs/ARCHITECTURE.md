# Runtime Architecture & Configuration Details

> This is an on-demand reference doc for `AGENTS.md`: it records the `scenes/main.tscn` scene tree, per-script responsibilities, the tech stack, key configuration files, and directory responsibilities. **Behavior rules and entry guidance: see `AGENTS.md`**; test commands: see `docs/TESTING.md`.

## Tech Stack

- **Engine:** Godot 4.6 (standard build suffices; no .NET). `project.godot` currently declares `4.6` and the `GL Compatibility` feature; both desktop and mobile use `gl_compatibility`.
- **Language:** Pure GDScript; Python files under `scripts/tools/` are offline tools (balance manager, doc generator, asset generators) depending only on the standard library (sprite generators additionally need PIL); they are not game-runtime dependencies.
- **Assets:** PNGs in `assets/sprites/`, WAVs in `assets/audio/`, and the UI font `assets/fonts/NotoSansSC.ttf`.
- **Data:** `data/balance.json` is the tunable-values source (top-level sections: world_scale, player, enemies, elites, boss, spawner, mothership, buffs, milestones, difficulty, progression, effects, tutorial, elite_turret_event, formation_strike_event); since 2026-07-31 it uses canonical JSON formatting (Tab indentation, no inline objects), maintained on disk by `balance_editor.py`. `data/translations.csv` is the zh/en text source; `.translation` files are generated by Godot's import and loaded at runtime.

## Main Scene Tree

`scenes/main.tscn` is the main scene tree and gameplay container:

```text
Main (scripts/main.gd)
├─ Starfield / Camera2D
├─ Player
├─ Spawner
├─ BulletPool / EnemyPool
├─ HUD (layer=2: leaves layer=1 — "above the world, below the HUD" — for MetaHealthFX)
├─ BuffUI / PauseUI / SettingsUI / GameOverUI / BaseUI
├─ StartPanel / ExitConfirm
├─ BackNavigator
├─ MetaHealthFX (created at runtime by main in _ready; layer=1; Meta HUD HP / hit full-screen post-processing)
├─ AimFrameLayer (created at runtime by main in _ready; world coords; aim-assist bracket overlay marking enemies; registered as GameState.aim_frame_layer)
├─ IntroCinematic (instantiated at runtime by main on new game; layer=35)
├─ ReturnCinematic (instantiated at runtime by main on homecoming; layer=35)
├─ OrbitalStrike (instantiated at runtime by main on sortie-continue; layer=24; orbital-strike clear animation)
├─ MothershipSummonWindow (instantiated at runtime by main when the mothership finishes charging; layer=24; hangar-window show)
├─ WarpGate (instantiated at runtime by main at the mothership berth when the window ends; world coords; warp-gate effect)
└─ EliteTurretEvent (created at runtime by main in _ready and registered with spawner for exclusivity)
└─ FormationStrikeEvent (created at runtime by main in _ready and registered with spawner; lowest-priority random event)
```

`scenes/` holds the main scene, player, regular enemies, Boss, bullets, mothership, intro/homecoming cinematics, and the tutorial scene; same-named behavior scripts usually live in `scripts/`. All dynamic gameplay entities should be parented under Main so they are visible to clear logic and test traversal.

## Per-Script Responsibilities

- `scripts/main.gd`: gameplay orchestration chaining spawning, milestones, Boss, mothership summon, homecoming, forfeit, BGM, page flow, and entry-transition animations (`_start_entry_sequence` after intro / sortie-continue).
- `autoload/game_state.gd`: global facade for score, HP, buffs, difficulty, RP, missions, routes, settings, and the signal bus. Value loading/querying, save read/write + corruption quarantine, the SFX pool, and the entity registry (`GameState.enemies`, `player_ref`, `player_hitbox`, pool references) are delegated to `BalanceService` / `SaveManager` / `SfxPlayer` / `EntityRegistry` (A2), with the public `GameState.*` syntax unchanged verbatim. Also owns **runtime assembly of gamepad default bindings** (`_bind_joypad_defaults()`: left-stick move / action keys / right-stick aim actions appended via InputMap, P0-1) and gamepad settings (`joy_aim_speed` / `joy_deadzone` setters + deadzone application + profile persistence).
- `scripts/player.gd`: WASD movement, mouse aim, auto-fire, fuel boost, fine move, phase dash, and hit handling. Buff visual feedback lives in the child node `scripts/player_buff_visuals.gd` (PlayerBuffVisuals) — procedural gun pods / shield arcs / halos / beacons plus an `engine_tint` multiply for the engine flame — driven by the `GameState.buffs_changed` signal. Aim assist (implementation details in `scripts/aim_crosshair.gd` / `scripts/aim_frame_layer.gd` and the `player.aim_assist` tier table): enemies roll an `Enemy.aim_marked` flag at spawn per `mark_ratio` (0.25); AimFrameLayer (on Main) draws the brackets; AimCrosshair (on Player, top_level) follows `aim_point()` and hides the system cursor; while the crosshair is inside a bracket, `_fire()` writes `Bullet.homing_target` onto new bullets (track time `homing_time`; close range flies straight, mid range steers harder, spiral convergence without orbiting); outside brackets it fires straight at the crosshair. `aim_point()` returns the smoothed aim point (weak stick inside brackets per `stick_factor`, short-range magnet pull outside, weak cone tracking outside), shared by hit-check / firing / crosshair drawing, advanced once per rendered frame; magnet and weak tracking share one distance falloff (`player.aim_assist.falloff`: full assist inside 400px → linear down to a 0.3 floor at 1400px).
- `scripts/spawner.gd`: wave-based spawning and special-slot scheduling. Regular waves refresh in groups on an interval ramp, with an elite wave every 3-4 regular waves; Boss / elites / events occupy the special slot (regular waves pause while one is active), followed by a breather wave after the kill. Regular waves currently instantiate `enemy.tscn` directly; Boss-3 adds use `GameState.enemy_pool.spawn()`. Do not assume "all enemies are already pooled" as current fact.
- `scripts/enemy.gd`, `mothership.gd`, `bullet.gd`, `laser_weapon.gd`: instantiable combat entities and weapon behavior.
- `scripts/boss.gd`: Boss entity driven by HP phase pattern tables (P1/P2/ENRAGE; tables `boss.phases.typeN` + telegraph windups), with type-differentiated enrage (`boss.enrage.type_*`; enrage slows the player ×0.35 instead of freezing), and difficulty tiers multiplied once in `_ready` (`boss.difficulty_scaling`). The fight anchor line `FIGHT_Y` is an offset from the view's top edge; all usages go through `_fight_anchor_y()`. Design: `docs/BOSS_REDESIGN.md`.
- `scripts/bullet_pool.gd`, `enemy_pool.gd`, `explosion.gd`, `starfield.gd`, `camera_shake.gd`, `spawn_telegraph.gd`: object reuse and the presentation layer.
- `scripts/hud.gd`, `buff_select.gd`, `base_console.gd`, `settings_ui.gd`, `pause_ui.gd`, `game_over_ui.gd`, `start_panel.gd`, `exit_confirm.gd`: pages and overlays. The start panel is a fully opaque standalone title screen (no gameplay shows through): brand area top-left + chamfered menu board center-left + decorative radar `scripts/start_radar.gd` right + decorative starfield `scripts/start_backdrop.gd` (fixed-seed static star points, unrelated to the in-game Starfield).
- `scripts/meta_health_fx.gd` (MetaHealthFX) + `assets/shaders/meta_health.gdshader` + `assets/shaders/crack_field_bake.gdshader`: Meta HUD HP / hit full-screen post-processing (design `docs/META_HUD_DESIGN.md`) — hit chromatic aberration / radial blur, direction-steered ripples, low-HP crack growth (Voronoi distance field pre-baked once: windowed mode SubViewport GPU 512², headless CPU 64² equivalent fallback, **both paths must stay formula-synced**), desaturation / vignette, and DYING heartbeat / breathing / HUD shake; at full HP the fullscreen ColorRect is hidden and `_process` early-exits (zero GPU, ≈zero CPU at rest). Values in `effects.meta_health`; the "reduce flashes" toggle lives in Settings → "Control Mode".
- `scripts/cinematic_fx.gd` (CinematicFx): shared static factory for cinematic / show effects — soft radial glow `soft_glow`, textured particles `particles` (≤96 per emitter), double-layer shockwave ring `shockwave`, layered energy beam `beam`, speed lines `speed_lines`, radial streaks `radial_streaks`; all driven `_process` paths allocate zero heap. Shared by the intro/homecoming cinematics and the mothership summon show.
- `scripts/intro_cinematic.gd`: intro cinematic director (6 shots, triggered on new game, `docs/INTRO_CINEMATIC.md`); the tree pauses while playing; Esc → BackNavigator `SKIP_INTRO`, any key / click skips; both finish and skip resolve through `finished` to resume.
- `scripts/return_cinematic.gd` + `scripts/dawn_station.gd`: homecoming cinematic director (7 shots, long-press B, `docs/RETURN_HOME_CINEMATIC.md`); architecture mirrors the intro, Esc → `SKIP_RETURN`, both finish and skip resolve through `finished` into the base UI (the tree stays paused; BGM fades -40dB during shot 7's fade-to-dark). `DawnStation` is a shared static factory for the station body (destroyed / holographic-ghost states), reused by intro shot 1, homecoming shots 2/3/4, and the base background.
- `scripts/orbital_strike.gd`: orbital-strike clear animation (triggered from the base "sortie again"): aim reticle → missile descent → hit beam / expanding ring; the tree stays paused; the strike frame (`struck`) drives clearing via main's registry (the Boss survives, ships explode one by one) and resumes play; values in `effects.orbital_strike`.
- `scripts/mothership_summon_window.gd` + `scripts/warp_gate.gd`: mothership summon show (triggered on charge completion; play does not pause; the player's input is locked with event-driven invulnerability during the show). While charging, main layers `_charge_fx` at the berth (contracting twin rings / suction particles / backlight); hangar window (charge line disconnects → maintenance arm releases → eject + shuttle start, layer=24, unified `finished` exit, `skip()` for tests to push through); when the window ends, main creates a warp gate at the berth (soft-lit gate core + inner swirl arcs + suction particles + front-lip occluder); the mothership DESCENDs through it, decelerating (travel `warp_in_drop`), then releases a twin-ring slow zone at position (`Enemy` / `Boss.apply_slow` short displacement slow) and immediately provides fire cover; DOCKING tows the player into the rescue pod (`player.enter_pod()` hides + disables hit-taking, RELEASE `exit_pod()` restores), after which resupply / stay / departure follow the original flow. Values in `effects.mothership_summon`.
- `scripts/elite_turret_event.gd`, `strike_carrier.gd`, `turret_battery.gd` (+ `scenes/turret.tscn`), `comm_overlay.gd`: elite turret event (`docs/ELITE_TURRET_EVENT.md`) — event state machine mutually exclusive with the Boss (`_boss_frozen` / `_boss_pending` / `_waves_paused` hooks in spawner), strike-carrier director, turret entity (weak-lock targeting, registered in the `enemy` group and `GameState.enemies`), and the bottom-left comms overlay.
- `scripts/formation_strike_event.gd`, `formation_craft.gd`, `formation_bomb.gd`: bombing-formation event (`docs/FORMATION_STRIKE_EVENT.md`) — lowest-priority random event (does not freeze the Boss, but **occupies the wave slot — regular waves pause while it runs**, via spawner's `_waves_paused` hook, mutually exclusive with the elite turret; interruptible by homecoming `abort()`), formation craft (registered in the `enemy` group and `GameState.enemies`), and fuze-timed falling bombs (warning ring shrinks with the fuze; AoE hits the player only).
- `scripts/back_navigator.gd`: unified back routing for PC Esc / gamepad `ui_cancel` / Android back. The tutorial is a standalone scene `scenes/tutorial.tscn`; `tutorial.gd` handles its own back behavior; the tutorial aligns with main-game logic: `_ready` also creates an AimFrameLayer (aim assist works in the tutorial), stage 1 force-marks the target drone, stage 4 long-press H charges → warp gate → mothership `begin_warp_in` → dock and resupply (hangar window skipped; entity path same as `main._on_summon_window_finished`).
- `scripts/mouse_trap.gd`: mouse-trap-in-window component (attached to Main; `GameState.mouse_lock` setting, default on, persisted in profile) — while the gameplay crosshair is active (not paused + system cursor hidden) and the window is focused, the mouse leaving the content area is warped back 1px inside the edge via `Input.warp_mouse()` (`mouse_exited` signal + per-frame `_process` guard); unfocused / paused / non-crosshair states always pass through (after pausing the mouse may leave the window freely, e.g. to click the OS close button and quit); prevents the crosshair's `get_global_mouse_position()` from freezing / jumping at the root, with zero changes to `aim_point()` / `AimCrosshair`.
